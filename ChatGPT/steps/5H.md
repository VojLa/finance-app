# Step 5H — Holding projection and rebuild

## Source-of-truth boundary

`InvestmentEvent` and `InvestmentMovement` are canonical history. `Holding` is a
rebuildable read model and must never alter, repair, or replace that history.

Step 5H is split into:

- **5H-A** — pure deterministic quantity projection;
- **5H-B** — pure exact persistence and weighted-average cost-basis projection;
- **5H-C** — atomic caller-transaction-owned database rebuild writer;
- **5H-D** — authorization, locking, orchestration, and any public rebuild API.

5H-A and 5H-B perform no I/O, generate no IDs or timestamps, and own no
transaction.

## Physical Holding persistence audit

The inherited PostgreSQL/SQLAlchemy contract is:

```text
id               TEXT primary key
symbol           TEXT not null
name             TEXT null
assetType        AssetType not null
quantity         NUMERIC(28,10) not null
avgBuyPrice      NUMERIC(28,10) not null
currency         TEXT not null
currentPrice     NUMERIC(28,10) null
currentValue     NUMERIC(28,10) null
unrealizedPnl    NUMERIC(28,10) null
realizedPnl      NUMERIC(28,10) null
assetId          TEXT null, FK Asset, ON DELETE SET NULL
listingId        TEXT not null, FK AssetListing, ON DELETE RESTRICT
accountId        TEXT not null, FK Account, ON DELETE RESTRICT
calculatedAt     TIMESTAMP(3) not null
updatedAt        TIMESTAMP(3) not null
UNIQUE(accountId, listingId)
```

The physical identity is exactly `(accountId, listingId)`. Projection requires
the canonical asset identity even though the physical `assetId` column is
nullable. `listing_asset_id` must equal `asset_id`; different listings are never
merged, even when they reference the same asset.

5H-B produces every non-temporal field that can be persisted without inference:

```text
account_id, asset_id, listing_id, symbol, name, asset_type,
quantity, avg_buy_price, currency,
current_price, current_value, unrealized_pnl, realized_pnl
```

`name`, current valuation fields, and P/L fields remain `null`. IDs and
`calculatedAt`/`updatedAt` are future 5H-C persistence metadata.

## Pure input and ordering

The builder receives one account ID and complete frozen event evidence. Event
evidence includes persisted event ID, account, type, date, external ID, and its
complete movement tuple. Movement evidence includes persisted identity,
account/event relation, kind, direction, quantity, currency, asset/listing
relation, source identity, price per unit, value amount, and value currency.

The builder accepts no caller-calculated quantity, average price, or cost basis.
It does not query events, assets, listings, prices, or FX.

Canonical event order is:

```text
event_date, event_id
```

5H-A validates the complete movement set using:

```text
event_date, event_id, movement_id
```

Persisted IDs are deterministic tie-breakers. Duplicate event or movement IDs,
contradictory account/event links, timezone-aware or sub-millisecond dates, and
malformed asset/listing relations fail the complete projection. Input order has
no effect and input objects are never mutated.

## Quantity movement contract

| Movement kind | Supported direction | Asset/listing relation | Quantity effect |
| --- | --- | --- | --- |
| `asset` | `in`, `out` | required and exact | `in` adds; `out` subtracts |
| `cash` | `in`, `out` | absent, or exact for linked dividend cash | none |
| `fee` | `out` only | forbidden | none |
| `tax` | `out` only | forbidden | none in 5H-A |
| any other value | — | — | fail closed |

Asset movements require non-blank `asset_id` and `listing_id`,
`listing_asset_id == asset_id`, an explicit `AssetType`, and canonical uppercase
`source_symbol == currency`. Zero final quantity omits the Holding. Any
intermediate or final negative position fails closed; short positions are not
specified.

## Event evidence matrix

5H-B validates movements as complete events, not as unrelated legs:

| Canonical event | Persisted evidence | 5H-B persistence result |
| --- | --- | --- |
| Trading212 buy | asset in with exact price/value/value currency; matching cash out | exact acquisition |
| Trading212 sell | asset out with exact price/value/value currency; matching cash in | exact disposal; average preserved |
| Trading212 dividend | asset-linked cash in, optional fee | quantity/cost unchanged |
| Trading212 fee | one fee out | quantity/cost unchanged |
| Trading212 currency conversion | one cash out and one cash in, optional fee | quantity/cost unchanged |
| Trading212 cash deposit/withdrawal/interest | exact cash leg, optional fee | quantity/cost unchanged |
| Anycoin grouped buy/sell | asset and matching cash legs with exact price/value currency | exact acquisition/disposal |
| Anycoin incoming transfer | asset in without acquisition value | unsupported while position remains open |
| Anycoin outgoing transfer | asset out | exact quantity disposal; average preserved |
| Staking reward | asset in, optional valuation but no adopted basis policy | unsupported |
| Airdrop | asset in, optional valuation but no adopted basis policy | unsupported |
| Adjustment | enum exists; 5G does not define a postable canonical shape | unsupported |
| Tax leg | no complete allocation policy or current 5G producer | unsupported in persistence projection |

An unsupported or incomplete event invalidates the complete persistence
projection. No known-cost subset is returned.

## Exact weighted-average cost basis

Cost basis is weighted-average cost per `(account_id, listing_id)`.

For an incoming trade acquisition:

```text
new_cost = existing_quantity × existing_average_cost + incoming_value
new_quantity = existing_quantity + incoming_quantity
new_average_cost = new_cost / new_quantity
```

The asset movement must contain positive exact `quantity`, `price_per_unit`,
`value_amount`, and uppercase `value_currency`. It must satisfy both:

```text
price_per_unit × quantity == value_amount
value_amount / quantity == price_per_unit
```

The event cash leg must have the opposite direction, the same exact amount, and
the same currency. A sale reduces quantity and preserves the existing average
for the remainder. A full sale removes the Holding. Sale before acquisition,
oversell, or outgoing transfer beyond the position fails closed. Sale price
never changes remaining average cost and 5H-B does not calculate tax-lot or
realized P/L.

An incoming transfer is an acquisition only when the canonical asset movement
contains the same complete exact basis evidence. Current Anycoin incoming
transfers do not, so they fail closed. Outgoing transfers preserve the remaining
average and never create realized P/L.

## Currency, fees, taxes, and valuation

`Holding.currency` is the currency of `avgBuyPrice`, derived only from the
canonical asset movement `value_currency`. It is not the asset symbol, account
currency, payout currency, latest purchase currency, or a current FX result.
Every acquisition for one listing must use the same cost currency. Mixed cost
currencies fail closed; 5H-B performs no FX lookup or conversion.

Fees and taxes remain separate canonical movements. They are not capitalized
because no complete allocation policy has been adopted. Current 5G auxiliary
fee legs are accepted and leave average cost unchanged. Tax-bearing persistence
history is rejected until a complete policy and canonical producer exist.

`current_price`, `current_value`, `unrealized_pnl`, and `realized_pnl` remain
`null`. 5H-B does not use market prices, latest FX, or approximate valuation.

## Decimal and fail-closed contract

All financial inputs and outputs are finite Python `Decimal` values exactly
representable by canonical `QUANTITY = NUMERIC(28,10)`. Float, non-finite,
zero/negative values where positive evidence is required, over-scale values,
precision overflow, multiplication/addition overflow, and a repeating
weighted-average result that cannot fit the physical column fail closed.

Calculations use elevated local Decimal precision, never round or truncate, and
revalidate every intermediate persisted value. One invalid event invalidates
the complete projection. The builders never repair or omit malformed history,
resolve identities, mutate input, use current time, or return partial output.

## Remaining scope

5H-C will own the atomic database rebuild, generated Holding IDs, and
`calculatedAt`/`updatedAt`. 5H-D will own authorization, locks, orchestration,
and any public rebuild endpoint.

5H-A and 5H-B add no migration, schema DDL, Holding repository or write, public
endpoint, automatic import hook, snapshot, valuation, price/FX lookup,
background work, queue, retry, importer change, or change to 5G writer
transaction ownership.
