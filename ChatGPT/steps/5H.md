# Step 5H — Holding projection and rebuild

## Source-of-truth boundary

`InvestmentEvent` and `InvestmentMovement` are canonical history. `Holding` is a
rebuildable read model and must never alter, repair, or replace that history.

Step 5H is split into:

- **5H-A** — pure deterministic quantity projection contract;
- **5H-B** — caller-transaction-owned database rebuild writer, after the required
  cost-basis policy is specified;
- **5H-C** — authorization, locking, orchestration, and any public rebuild boundary.

5H-A performs no I/O and owns no transaction.

## Physical Holding schema audit

The inherited PostgreSQL/SQLAlchemy contract is:

```text
id               TEXT primary key
symbol           TEXT not null
name             TEXT null
assetType        AssetType not null
quantity         NUMERIC(28,10) not null
avgBuyPrice      NUMERIC(28,10) not null
currency         TEXT not null
currentPrice     NUMERIC(28,10) null
currentValue     NUMERIC(28,10) null
unrealizedPnl    NUMERIC(28,10) null
realizedPnl      NUMERIC(28,10) null
assetId          TEXT null, FK Asset, ON DELETE SET NULL
listingId        TEXT not null, FK AssetListing, ON DELETE RESTRICT
accountId        TEXT not null, FK Account, ON DELETE RESTRICT
calculatedAt     TIMESTAMP(3) not null
updatedAt        TIMESTAMP(3) not null
UNIQUE(accountId, listingId)
```

The physical identity is exactly `(accountId, listingId)`. Asset identity is
validated through `AssetListing.assetId`; different listings are never merged,
even when they reference the same asset.

## 5H-A input

The pure builder receives one account ID and a complete tuple of movement inputs.
Each input carries only persisted ordering, movement, and joined listing-relation
evidence:

```text
movement_id
event_id
account_id
event_date
kind
direction
quantity
currency
asset_id
listing_id
listing_asset_id
source_symbol
source_asset_type
```

The future adapter must load the complete active canonical history. The builder
does not query events, movements, assets, or listings.

Canonical order is:

```text
event_date, event_id, movement_id
```

All values are persisted, deterministic tie-breakers. Duplicate movement IDs,
blank ordering IDs, timezone-aware timestamps, and timestamps not exactly
representable by `TIMESTAMP(3)` fail closed.

## Movement semantics

| Movement kind | Supported direction | Asset/listing relation | Holding quantity effect |
| --- | --- | --- | --- |
| `asset` | `in`, `out` | required and exact | `in` adds; `out` subtracts |
| `cash` | `in`, `out` | absent, or exact for asset-linked dividend cash | none |
| `fee` | `out` only | forbidden | none |
| `tax` | `out` only | forbidden | none |
| any other value | — | — | fail closed |

Asset movements require non-blank `asset_id` and `listing_id`,
`listing_asset_id == asset_id`, an explicit `AssetType`, and canonical uppercase
`source_symbol == currency`. Missing or contradictory identity is corruption.

Every movement quantity is a positive finite `Decimal` exactly representable by
the canonical `QUANTITY = NUMERIC(28,10)`. Float, zero, negative, over-scale,
overflow, and non-finite values fail closed. Aggregate addition uses an elevated
local Decimal precision and every intermediate result is revalidated against
`QUANTITY`; no rounding or truncation is allowed.

## Projection output

The immutable output is an account projection containing a deterministically
ordered tuple of plans with only exactly derivable physical Holding fields:

```text
account_id
asset_id
listing_id
symbol
asset_type
quantity
```

Plans are ordered by `listing_id`. A final exact zero quantity is omitted.
Any intermediate or final negative quantity fails closed because short positions
are not currently specified or supported.

## Cost-basis boundary

5H-A does **not** calculate `avgBuyPrice`, cost basis, realized P/L, or Holding
currency. Current history can contain incoming asset transfers, staking rewards,
or airdrops without an exact acquisition value. It would therefore be unsafe to
apply an approximate weighted average, current prices, or current FX.

The following physical fields remain outside the 5H-A output:

- `id`, `name`, `avgBuyPrice`, and `currency`;
- current price/value and realized/unrealized P/L;
- `calculatedAt` and `updatedAt`.

5H-B must not write Holding rows until an exact policy supplies every required
physical field for all supported movement histories.

## Fail-closed contract

One invalid movement invalidates the complete projection. The builder never:

- repairs or omits malformed movement history;
- resolves assets/listings or merges symbols;
- mutates its input;
- uses current time, market prices, or FX;
- creates a Holding or any other database record.

Equal inputs produce structurally equal outputs. Permuting valid input order
produces the same output after canonical sorting.

## 5H-A scope exclusions

5H-A adds no migration, schema DDL, repository, database writer, API endpoint,
automatic import hook, snapshot, valuation, price/FX lookup, queue, retry, or
change to 5G posting behavior or transaction ownership.
