# Step 5L — Snapshot-backed portfolio and dashboard reads

Step 5L replaces presentation-time financial authority with exact immutable
snapshot evidence in bounded stages. The existing basic portfolio endpoint
remains an unchanged legacy reader until the later integration stages.

- **5L-A** — pure single-account portfolio snapshot view (implemented);
- **5L-B** — persisted exact AccountSnapshot reader (planned);
- **5L-C** — authorized portfolio snapshot API (planned);
- **5L-D** — multi-account portfolio aggregation (planned);
- **5L-E** — dashboard snapshot projection (planned);
- **5L-F** — dashboard/portfolio API integration (planned);
- **5L final audit** — cross-boundary contract and integration audit (planned).

## 5L-A pure boundary

`build_portfolio_snapshot_view()` accepts one frozen
`PortfolioSnapshotSource` containing complete, already validated immutable
AccountSnapshot evidence and frozen item evidence. It returns one frozen
`PortfolioSnapshotView` with Account metadata, exact snapshot metadata,
output-currency summary values, and a tuple of immutable positions.

The input boundary contains no ORM object. Account and Asset types,
SnapshotGranularity, and SnapshotSource are pure presentation enums; the future
5L-B persisted adapter owns the explicit mapping from persisted domain values.
The view exposes no user or membership identity, lineage or market-evidence ID,
exchange-rate audit, internal JSON, or PriceSnapshot identity.

## Exact values and currencies

All financial values remain `Decimal`. The contract validates the physical
limits without changing values:

- aggregate and converted position values: `MONEY NUMERIC(18,6)`;
- quantity, unit price, native value, cost basis, native cost basis, and
  position unrealized P/L: `QUANTITY NUMERIC(28,10)`;
- allocation: `PERCENTAGE NUMERIC(8,4)`;
- metadata timestamps: naive `TIMESTAMP(3)`.

Currencies are exactly three uppercase ASCII letters. The view currency equals
the AccountSnapshot output currency. Converted position `value_currency` and
`cost_currency` equal that output currency. Account, price, native value, and
native cost currencies remain independent explicit evidence and are never
converted by 5L-A.

The projection performs no rounding, binary floating-point conversion, FX
lookup, rate inversion or chaining, price selection, missing-data repair, or
fallback.

## Exact invariants

The projection fails unless:

```text
total_value
  == cash_value + investment_value - liabilities_value

unrealized_pnl_value
  == investment_value - investment_cost_basis

sum(position.value)
  == investment_value

sum(position.cost_basis)
  == investment_cost_basis

sum(position.unrealized_pnl)
  == unrealized_pnl_value
```

Each position also proves `native_value == quantity * price_per_unit` and
`unrealized_pnl == value - cost_basis`. Stored allocation remains the sole
allocation authority and is validated against
`position.value / positive investment_value * 100`. A positive portfolio must
sum exactly to 100 at the persisted percentage scale. A zero portfolio and any
zero-value position require zero allocation.

## Account shapes and ordering

Broker, exchange, and crypto-wallet snapshots support positions. An empty
investment snapshot returns an empty tuple and structural-zero investment
values. Credit-card, loan, and mortgage snapshots return summary-only views:
positions, cash, investment values, and financial metrics are structural zero,
while liabilities are a nonnegative magnitude and total value is its exact
negative. Bank, cash, and savings fail closed because their physical
AccountSnapshot contract is not yet supported.

Positions use one canonical ordering:

```text
asset_type, symbol, listing_id, item_id
```

Input permutation therefore cannot change the resulting view. Duplicate item
IDs, listing IDs, or asset/listing identities fail closed; symbol and name are
presentation fields, not identity.

## Failure and deferred scope

Every evidence failure raises
`PortfolioSnapshotProjectionError("Portfolio snapshot evidence cannot produce a complete view.")`.
The public message contains no identity, currency, timestamp, amount, or
internal cause.

5L-A has no database access, ORM, repository, authorization, FastAPI endpoint,
clock, UUID generation, serialization, side effect, migration, dashboard,
multi-account aggregate, frontend change, or adapter for the legacy portfolio
endpoint. Those boundaries remain assigned to 5L-B through 5L-F.
