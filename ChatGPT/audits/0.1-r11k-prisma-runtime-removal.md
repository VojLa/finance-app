# 0.1-R11-K — Prisma runtime and operational script removal

## Verdict

`R11-K VERDICT: PASS`

The application and toolchain no longer contain a Prisma client, schema,
generator, runtime dependency, seed, studio command, or executable migration
path. SQLAlchemy is the complete runtime mapping and Alembic is the sole
executable schema owner. `prisma/migrations/` remains unchanged as immutable,
hash-verified historical SQL evidence.

## Implementation

- Removed `@prisma/client`, `prisma`, `bcryptjs`, their obsolete type/tooling
  dependencies, `src/lib/prisma.ts`, account-access/decimal barrels, Prisma
  configuration/schema/seed, and old parity/archive wrappers.
- Replaced the category seed with one Python-owned advisory-locked transaction.
  Reserved identities replay exactly and inconsistent existing state fails
  without overwrite.
- Docker and frontend CI no longer generate Prisma or provide PostgreSQL access
  to Next.js.
- Database CI reconstructs the inherited baseline from committed SQL and upgrades
  through Alembic. The historical archive is verified by Python aggregate hash,
  never executed.
- Package policy rejects Prisma-named scripts and removed runtime dependencies.
- Current architecture, setup, ownership, and contributor documentation now
  describes the completed cutover.
