# R11-G audit — manual investments and symbol detail

Date: 2026-08-10

Verdict: **PASS**

## Scope reviewed

- Python manual investment request, service, repository, and API boundary.
- Canonical event/movement writes, revision update, and Holding rebuild.
- Post-commit snapshot/current readiness coordination.
- Authorized symbol position and event-history read.
- Generated TypeScript contract, thin same-origin adapter, manual-add page, and
  symbol-detail page.
- Shared manual asset/listing resolution used by imports and manual commands.

## Findings

- The active manual browser flow has no Prisma, TypeScript ledger, Holding,
  snapshot, FX, price, or valuation ownership.
- A command writes its event, complete movement set, canonical revision, and
  rebuilt Holdings in one caller-owned database transaction. Failure rolls the
  full mutation back.
- Idempotency is serialized and payload-sensitive. Exact replay creates no
  duplicate rows; changed reuse conflicts; concurrent replay is safe.
- Snapshot readiness runs after the canonical commit because provider work
  cannot be part of the database transaction. Its unavailable/conflict state is
  explicit, and replay can safely retry readiness.
- Currency conversion records both direct currency legs. No supported action
  can create an empty event.
- Symbol detail is authorization-scoped and read-only. Exact database numeric
  values remain fixed-scale strings through Python, generated contracts, and
  browser state.
- Remaining TypeScript snapshot and ledger compatibility modules are not used
  by these active paths and are assigned to R11-H/R11-I removal.
