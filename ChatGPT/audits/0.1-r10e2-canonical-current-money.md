## Root cause and fix

The affected Pydantic serializers used `format(value, "f")`. That preserves a
Decimal's internal exponent, so an exact composed MONEY value could cross the
wire as `1800.00000000000000` instead of canonical `1800.000000`. The browser's
strict six-decimal MONEY validator correctly rejected that payload.

`app.shared.numeric_serialization` is now the single public fixed-scale
formatter. It reads the repository's physical SQLAlchemy Numeric contracts,
requires a finite Decimal, quantizes under sufficient local Decimal precision,
compares the quantized value to the original before serialization, enforces the
integral precision limit, and emits fixed-point output at the exact target
scale. Equality permits removal of internal trailing zeros; any material digit
beyond the target scale fails rather than rounding.

Canonical negative zero is deliberately emitted without a sign:
`Decimal("-0.000000") -> "0.000000"`.

## Exact behavior

- `0`, `75`, and `75.1` become `0.000000`, `75.000000`, and `75.100000`.
- `1.12345600000000` becomes `1.123456` without financial rounding.
- `1.1234567` fails closed.
- `1000000000000.000000` exceeds MONEY's integral range and fails closed.
- NaN and positive/negative Infinity fail closed.
- QUANTITY remains ten-decimal, RATE eight-decimal, and PERCENTAGE
  four-decimal; no Decimal-wide six-place coercion exists.

## Authenticated and browser acceptance

HTTP 200 for portfolio and dashboard and preserves finance row counts. The
mixed `User.baseCurrency=CZK` / `Account.currency=EUR` liability scenario
returns:

- portfolio global liabilities `1800.000000` CZK and total `-1800.000000`;
- portfolio account liabilities `75.000000` EUR and total `-75.000000`;
- dashboard global liabilities `1800.000000` CZK;
- dashboard account liabilities `75.000000` EUR.

The same canonical mixed payload passes the actual authenticated Next route,
server workflow validator, browser client, portfolio/dashboard model, and
presentation formatter. Requests are limited to `/portfolio/current` and
`/dashboard/current`; no snapshot-recalculate, legacy finance, `/api/rates`,
frontend FX, or frontend arithmetic path was introduced. Variable scale,
exponent, plus prefix, numeric JSON, non-finite-like text, and overflow remain
rejected by the unchanged browser MONEY contract.

No-baseline remains a safe `409 current_value_unavailable`; invalid bearer
authentication remains `401 invalid_session_token`. D1 backfill and
newest-invalid/no-older-fallback behavior remain unchanged.
