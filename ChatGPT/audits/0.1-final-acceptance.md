## Architecture boundary

The implemented snapshot path has the target boundary:

```text
browser
  -> bodyless Next session adapter
  -> short-lived internal token
  -> FastAPI refresh/exact read
  -> PostgreSQL snapshot evidence
```

That boundary does not cover the full 0.1 main scenario. Account creation and
all three import flows still require Next routes that own Prisma writes,
parsing, canonical posting orchestration, holdings rebuild and snapshot
follow-up. Therefore the repository contradicts the 0.1 rule that critical
domain logic is not a Next.js source of truth.

Python remains modular and the implemented snapshot projection/read layers
have explicit pure, repository, service and API boundaries. Alembic owns the
schema and generated OpenAPI owns Python HTTP transport types.

## Authentication

**PASS**

The 5M final audit proves the NextAuth-to-HS256-to-Python verifier bridge,
exact subject, optional email, issuer/audience, token-per-request behavior,
missing-session rejection, cookie non-forwarding and token non-exposure.

## Accounts

Python account lifecycle is implemented and PostgreSQL-tested for create,
list, update, archive/restore, main currency, supported types, roles,
nondisclosure, rollback and clean-database creation.

The browser account page calls `/api/accounts`. That route imports Prisma,
validates account types in TypeScript, creates the account and nested owner
membership, edits business fields and performs destructive domain cleanup.
The in-process audit confirms the authenticated POST completes with a Prisma
write and zero FastAPI requests.

**Backend: PASS. Frontend: MISSING. Release impact: blocker.**

## Import frontend

The import page calls `/api/import/raiffeisenbank`,
`/api/import/trading212`, `/api/import/anycoin` and `/api/import/status`.
Each provider route reads the browser files and calls TypeScript
`importCsvFilesAsync`. Status queries Prisma and constructs a separate issue
shape. In-process tests execute all three routes and prove zero FastAPI
requests.

Multi-file orchestration also remains in the legacy TypeScript path instead of
one Python-owned logical batch/post-processing workflow.

**MISSING. Release impact: blocker.**

## Observability

FastAPI has stable error envelopes, internal request IDs and logs that exclude
authorization/body data. Import batches retain status, rows, validation
issues and error logs; snapshot validation/calculation errors are distinct.

The browser import status route bypasses Python and reconstructs errors from
Prisma. Therefore technical backend observability is **PASS**, while the
required browser workflow is **MISSING**.

## Clean-database E2E

A dedicated migrated PostgreSQL database starts with zero users, accounts,
imports and financial rows. The audit creates a user, three Python-owned
accounts with persisted owner memberships and one registered batch for each
mandatory source.

The scenario cannot continue to representative upload, canonical data,
holdings, snapshots, exact reads and deterministic replay for all three
sources because:

- no representative Python source fixtures are committed;
- the Python source parsers are generic;
- the browser uses TypeScript account/import business routes;
- the required price/FX provider boundary is incomplete.

The passing probe records the exact stopping point and does not mislabel batch
registration as E2E success.

**MISSING. Release impact: blocker.**

## Browser E2E

Login/session bridging and the portfolio/dashboard snapshot flows are
implemented. Account creation and import/status remain legacy business
workflows. The main scenario therefore still needs Next.js business logic and
cannot satisfy the architecture lock.

**MISSING. Release impact: blocker.**

## Security isolation

**PASS at implemented Python boundaries.**

Persisted membership protects accounts, imports, refresh and exact reads;
foreign/missing/archived identities follow nondisclosure contracts. Token
subject and server-created selectors cannot be overwritten. Upload traversal,
size, content type, checksum and malformed-file cases fail safely.

The remaining Next business paths are architectural blockers rather than
evidence of a demonstrated cross-user leak.
