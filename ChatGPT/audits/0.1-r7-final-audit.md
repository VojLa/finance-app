## Production architecture inventory

The active production call graph is:

```text
persisted NetWorthSnapshot
→ Python portfolio_history repository
→ exact validation, duplicate collapse, and deterministic downsampling
→ GET /api/v1/portfolio/history
→ generated OpenAPI contract
→ authenticated server transport with a fresh internal JWT
→ GET /api/portfolio/history
→ strict browser validator
→ explicit loading/ready/empty/error state

```

The Python module imports the `User` and `NetWorthSnapshot` database models
and no other financial model. Its repository contains two SELECT operations
and no INSERT, UPDATE, DELETE, row lock, advisory lock, provider call, cache,
task, or refresh. AST and source inventories reject Transaction, ledger,
InvestmentEvent, InvestmentMovement, Holding, AccountSnapshot, price, FX,
market-data, import, and provider dependencies.

The service reads its injected clock exactly once and owns
`REPEATABLE READ, READ ONLY`. The database transaction closes before pure
selection. Dedicated PostgreSQL tests prove the session is idle after success
and failure and physical row counts do not change.

The active Next route has no Prisma, `accountAccess`, or TypeScript history
service dependency. A complete production occurrence scan finds
`getPortfolioSnapshotHistory` only as an unexported dead implementation in
`src/modules/snapshots/service.ts`; it has no active importer or consumer.

## Python history contract

The range contract is exactly `1W`, `1M`, `3M`, `6M`, `1Y`, and `ALL`, with
`1Y` as the default. Unit coverage includes invalid ranges, aware and
sub-millisecond clocks, month-end and leap-year boundaries, inclusive lower
boundaries, `ALL`, and future exclusion.

Persisted `User.baseCurrency` owns the response currency. The repository
filters by authenticated principal and that exact currency; it never converts
or mixes other-currency snapshots. Public callers cannot select a user,
account, or currency.

Each financial field is validated as exact `NUMERIC(18,6)`. Negative cash and
net worth remain valid, while portfolio and liabilities must be nonnegative.
NaN, infinity, overprecision, overflow, duplicate IDs, inconsistent formulas,
and conflicting equal timestamps fail the whole response. No value is rounded
or repaired.

Equal timestamps collapse deterministically by
minute/hour/day/week/month granularity and then snapshot ID. Final timestamps
are unique and ascending. Downsampling is deterministic, value-independent,
bounded to 512 points, and retains the first and last point for 513-point and
multi-thousand-point inputs. Empty history is a valid `200` with no synthetic
point.

The public point exposes only timestamp, cash, investment value, liabilities,
and net worth. It does not infer historical deposits or cost basis and does
not expose snapshot lineage, provider metadata, prices, rates, or internal
calculation fields.

## Browser boundary and state audit

The Next route accepts only the optional `range` parameter. Unknown,
duplicate, caller identity, account, currency, date, and limit parameters are
rejected. It authenticates the browser session, creates a fresh server JWT,
and makes exactly one generated Python GET with no body. Browser Cookie and
Authorization headers are not forwarded. Responses are no-store.

The in-process acceptance exercises:

```text
browser GET
→ Next route
→ NextAuth
→ fresh internal JWT
→ Python GET
→ server validation
→ browser validation
→ history state
→ chart projection
```

It verifies the JWT subject/email, absence of browser credentials on the
Python hop, exact MONEY byte preservation, one browser and one Python request,
and no snapshot refresh. Safe failures expose no backend URL, bearer token,
raw body, request ID, traceback, or SQL detail.

The runtime parser requires exact top-level and point key sets, the requested
range, current portfolio currency, canonical six-decimal MONEY strings,
canonical millisecond UTC-naive timestamps, ascending unique timestamps, and
at most 512 points. Numeric JSON values, exponent notation, missing scale,
plus signs, leading zeros, overflow, invalid timestamps, extra fields,
missing fields, duplicate/descending points, malformed JSON, backend errors,
and network errors fail closed rather than becoming false empty history.

History waits for a ready current portfolio. A new `NetWorthSnapshot` identity
or range starts one request. Late stale responses cannot overwrite a newer
range. Chart mode and local account selection start no request. Current cards,
positions, cash/deposit breakdowns, aggregate/account selection, and dashboard
remain isolated from history state.

## Chart audit

The chart exposes only persisted `netWorthValue` and `investmentValue` modes.
It has no deposits, cost-basis, realized/unrealized P/L, inferred baseline,
FX, legacy invested value, or synthetic current point.

Exact strings remain tooltip authority through `formatSnapshotAmount`.
Response currency owns the tooltip and axis; no CZK-specific label exists.
There is exactly one history `Number(exactValue)` conversion across the active
history chart boundary. It is documented and isolated to the Recharts
coordinate after strict validation, is never used for finance or tooltip
output, and cannot flow back into current portfolio state. Chart guards reject
financial `Math`, reduction, sorting, and fixed-point recomputation.

Empty history has explicit text, one point remains ready and visible, and
negative net worth and zero investment remain representable.
