# R11-I audit — TypeScript import legacy removal

Date: 2026-08-10

Verdict: **PASS**

## Execution-order note

Repository inspection showed that the unused TypeScript import registry was
the final consumer of the TypeScript snapshot engine. R11-I was therefore
executed before R11-H so R11-H can satisfy its zero-runtime-import acceptance
condition without weakening or partially disabling an import path.

## Scope reviewed

- Browser import page and typed client.
- Generic import and explicit finalization routes.
- Python staged API transport and finalization recovery.
- TypeScript import registry, service, source parsers, compatibility barrels,
  provider/status routes, and package dependencies.
- Three-source, market-backed, failure/replay, and multi-file PostgreSQL
  acceptance.

## Findings

- The production browser uses only `POST /api/import` and
  `POST /api/import/finalize`.
- Next.js preserves exact file bytes, checks the session and bridge allowlist,
  and delegates every parse, normalize, deduplicate, classify, canonical-post,
  Holding rebuild, and snapshot-finalization operation to Python.
- No production TypeScript import registry, parser, deduplication, canonical
  writer, Holding/snapshot hook, compatibility barrel, provider-specific route,
  or batch-status route remains.
- `papaparse` and its TypeScript declarations have no consumer and were removed.
- Required PostgreSQL acceptance exposed two stale assertions from earlier
  architecture changes. The tests now require both native EUR and requested CZK
  account snapshots where applicable, select parity in the NetWorth output
  currency, and seed source-qualified CNB pivot evidence. No production finance
  behavior was changed to accommodate them.
