## Scope and production correction

R8 replaces registration-only and historical-SHA acceptance assertions with a
current clean-database proof and adds a remote Frontend gate. No schema,
migration, provider, snapshot calculation, import orchestration, public
request, or response contract changes were made.

The clean scenario exposed one narrow production defect in dashboard
presentation: valid allocations such as `1 / 3` were rejected because the
projection required the unrounded ratio itself to fit `NUMERIC(8,4)`.
`dashboard_snapshot/projection.py` now uses deterministic Decimal largest
remainder allocation. It never changes position values, produces canonical
four-decimal percentages, and makes every non-empty allocation set sum exactly
to `100.0000`. Regression coverage includes a `2 / 3` and `1 / 3` split.

## Replay and failure

Each source is re-imported with byte-distinct but row-equivalent input. The
public contract returns zero imported rows and `not_required`; canonical
tuples, Holdings, market IDs, snapshot IDs, NetWorth IDs, portfolio JSON,
dashboard JSON, and history JSON remain unchanged.

A deterministic Twelve Data 429 during a new coordinated manual refresh
returns the generic unavailable error. Canonical evidence and Holdings stay
committed, while price, FX, AccountSnapshot, and NetWorth row IDs remain
exactly unchanged. After restoring the HTTP seam the same public request
succeeds. No raw provider response, SQL, traceback, token, or raw import row is
present in the error.
