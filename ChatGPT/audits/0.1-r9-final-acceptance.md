## 7. Architecture

The active architecture is:

```text
browser
  -> thin Next.js session adapter
  -> fresh internal JWT
  -> Python FastAPI
  -> PostgreSQL
```

Python owns account, import, posting, holdings, market evidence, snapshot,
portfolio, dashboard, and history domain behavior. Next.js owns browser
presentation, NextAuth, safe transport adaptation, and approved chart-leaf
number conversion.

## 8. Auth

Next routes resolve the NextAuth session on the server. The shared server-only
transport issues a new short-lived JWT immediately before each FastAPI
request, uses the session user ID as the subject, forwards neither browser
cookie nor browser authorization, and keeps tokens/configuration out of client
modules and responses. Python authorization derives from persisted
memberships.

## 9. Accounts

Python exposes create, list, update, archive, and restore. The active browser
account page uses same-origin thin routes backed by the generated Python
contract. Account type/currency validation, role authorization, owner
membership creation, foreign-principal nondisclosure, and archived-account
nondisclosure remain Python-owned. Clean-database creation is exercised in the
R9 main scenario.

## 10. Imports

The active browser flow is:

```text
browser -> POST /api/import -> thin Next adapter
        -> create -> upload -> parse -> normalize
        -> deduplicate -> classify -> post -> final Python batch read
```

Exact bytes are preserved. There is no `importCsvFilesAsync`, active
TypeScript parser, caller posting plan, or Prisma status reconstruction in
this call graph. Submitted files execute sequentially through one Python batch
and one post-process per file, with safe partial completion if a later file
fails.
