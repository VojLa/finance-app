## Old and new behavior

Before R10-C, the global dashboard model already carried
`summary.netDepositsValue`, but `SnapshotSummaryCards` did not render it. The
account projection validated the presentation summary's net-deposit value and
discarded it, so the account API/model/card could not present it.

R10-C retains `net_deposits_value` in `DashboardAccountCard`, serializes the
required `netDepositsValue` as canonical MONEY, validates it at the active
server/browser boundary, and renders `Čisté vklady` in both summary and account
cards. Zero and negative values remain visible.

## Financial authority

Global dashboard net deposits continue to come only from the primary portfolio
aggregate in `User.baseCurrency`. They are never reconstructed by adding
account cards. For mixed currencies, the account card copies the deliberately
independent net-deposit value from the exact R10-B1/B2 companion in
`Account.currency`; for equal currencies, one primary identity serves both
contracts. No relabeling, read-time FX, live provider call, financial
arithmetic, ledger reconstruction, or fallback was added.

Missing, duplicate, wrong-version, wrong-currency, or otherwise corrupt
companion evidence continues to return the existing safe 409 response. The
dashboard read creates and mutates no financial rows.
