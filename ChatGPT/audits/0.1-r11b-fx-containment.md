# 0.1-R11-B — FX/Yahoo safety containment

## Verdict

`R11-B VERDICT: PASS`

New snapshot and current-value selection is source-qualified. A persisted
Yahoo/ECB/manual row cannot win a CNB evidence request solely because its pair
and timestamp are newer or equal. The remaining TypeScript compatibility FX
reader can only read persisted CNB rows, performs no provider request or FX
write, and fails closed when approved evidence is unavailable.

This step intentionally does not delete or rewrite historical FX rows and does
not yet perform the final Twelve Data direct-pair cutover owned by R11-J.

## Implementation

- `AccountSnapshotEvidenceRepository` requires an explicit
  `ExchangeRateSource` and filters it in SQL.
- Snapshot and D2 current-value validation carry the same explicit source
  through candidate validation, latest selection, current valuation, and
  historical event-date selection.
- The compatibility TypeScript rates reader filters `source=cnb`.
- Yahoo FX fetch/upsert code was removed. Missing conversions now raise instead
  of being treated as identity.
- `scripts/audit_exchange_rates.py` performs a read-only source-count,
  cross-source-collision, duplicate-identity, and invalid-row audit.
