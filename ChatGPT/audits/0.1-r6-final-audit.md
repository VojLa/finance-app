## Exact decoder, projection, and aggregation

The canonical decoder accepts only a JSON object with `[A-Z]{3}` keys and
canonical fixed-scale MONEY strings. Values require exactly six decimals,
canonical sign and leading-zero forms, finite Decimal values, and
`NUMERIC(18,6)` range. It rejects `None`, JSON numbers, booleans, null, lists,
nested objects, whitespace, plus signs, exponent notation, NaN, Infinity,
overprecision, overflow, and rounding.

Negative cash and net deposits are valid. An empty object is valid only with a
zero scalar. A sole output-currency item must equal the scalar. Multi-currency
scalar coherence remains owned by the AccountSnapshot writer because the
persisted exchange-rate field is not a safe independent revaluation contract;
the reader does not invent a new FX algorithm.

The pure currency amount, source, summary, account, and aggregate contracts are
frozen slot dataclasses. Projection validates canonical order, uniqueness,
MONEY precision, and coherence, then propagates the validated tuples without
financial transformation.

Multi-account aggregation groups only identical original currency codes and
uses exact Decimal MONEY addition. It performs no FX lookup or conversion,
sorts the result by currency, retains negative values and a currency whose sum
cancels to zero, creates no synthetic currency, and fails closed on overflow.
The representative account evidence converges to:

```text
cash:
  CZK 10000.000000
  EUR 12.340000
  USD -50.000000

net deposits:
  CZK 25000.000000
  EUR 500.000000
```

## Public API, authorization, and dashboard

Single-account, nested-account, and aggregate portfolio summaries require both
sorted currency/amount arrays. `PortfolioCurrencyAmountResponse` requires
`currency: string` and exact string-serialized `amount`. OpenAPI and
`src/generated/python-api.ts` agree, and the generation drift check passes.

Dedicated PostgreSQL acceptance uses actual readers, services, and FastAPI
routes with exact snapshot guards. It proves persisted JSONB, exact snapshot
IDs, account breakdowns, aggregate breakdowns, unchanged scalar totals,
lineage, deterministic ordering, negative cash, and portfolio/dashboard
scalar parity.

Missing or malformed breakdown evidence returns the existing generic
fail-closed response and never falls back to another or latest snapshot.
Foreign, missing, and archived accounts remain nondisclosing. Public responses
do not expose physical JSONB names, exchange rates, price/FX identities,
provider metadata, credentials, bearer tokens, SQL detail, traceback, or
internal item lineage beyond the approved contract.

Dashboard production and schema remain unchanged. Its response contains no
cash/deposit breakdown arrays while its existing scalar fields remain equal to
the portfolio aggregate.

## Frontend workflow and UI

The in-process acceptance executes:

```text
browser POST /api/snapshot-workflow/portfolio
-> Next route
-> FastAPI snapshot refresh
-> FastAPI exact portfolio read
-> page state
-> page model
-> SnapshotCurrencyBreakdown
```

One browser request produces exactly two server-owned FastAPI requests. The
transport forwards no browser cookie or token, issues fresh server bearer
tokens, and returns no secret. Portfolio data reaches page state unchanged.
The aggregate summary is the exact `data.summary` reference; selected accounts
use the exact account summary reference. Account selection is a pure local
lookup and performs no additional request.

The UI presents scalar `Hotovost` and `Čisté vklady` cards in `view.currency`,
then `Hotovost podle měny` and `Čisté vklady podle měny` from the active
server summary. The component preserves server order with `items.map`, exact
Decimal strings, negative values, zero values, and long precise values. Empty
arrays render explicit text and no synthetic row.

Each panel is a section whose `aria-labelledby` points to its heading, and
currency/value pairs use `dl`, `dt`, and `dd`. Negative amounts remain textual,
the account selector retains `aria-pressed`, and responsive grids begin with
one column without explicit horizontal overflow.

Source guards cover the page, page model, breakdown component, and holdings
table. They reject `Number`, `parseFloat`, `parseInt`, `Math`, `toFixed`,
`reduce`, `sort`, `Map`, `Object.fromEntries`, rate endpoints, latest FX, and
legacy portfolio fallbacks. The one pre-existing Recharts allocation-leaf
`Number` conversion remains outside the breakdown contract and has its own
isolation guard.

## History isolation

`/api/portfolio/history` remains chart-only. History state can only feed
`PortfolioLineChart`; it cannot set the current scalar summary, either
breakdown, positions, output currency, account selection, or account data.
R6 does not claim portfolio history complete. R7 remains a separate planned
step.
