## Runtime boundary

FastAPI now owns transaction list/filter/pagination/create/update/delete and category
list/create/update/delete. Both active Next routes retain only session verification,
request allowlisting, internal transport, and safe error mapping. The pages use
generated OpenAPI aliases through typed same-origin clients. Neither route imports
Prisma or the TypeScript account-access authority.

The obsolete TypeScript category-rule executor and compatibility barrels were
removed. Calls from the inactive legacy TypeScript import registry were also removed;
the active import flow already classifies and posts in Python.

## Financial and integrity behavior

- Manual amounts enter Python as exact positive Decimal values and are stored with
  canonical signs; responses serialize exact strings.
- A new create, replacement update, or tombstone delete appends exactly one
  account-scoped canonical revision in the same database transaction.
- Idempotency uses deterministic UUIDv5 identities plus a PostgreSQL transaction
  advisory lock. Exact replay does not consume a revision; reuse with different
  content fails with 409.
- Account roles and category ownership are enforced in Python. Foreign accounts and
  categories do not leak; viewers cannot write.
- Pair/split edits fail closed rather than corrupting compound transactions.
- Default categories are immutable. User hierarchy updates reject foreign parents,
  self-parenting, and cycles. Schema-owned `SET NULL`/cascade effects make deletion
  safe for transaction and rule references.

PostgreSQL integration exposed and prevented a duplicate canonical-state insert:
Alembic already installs the `Account_initializeCanonicalState` trigger. Account
creation therefore continues to rely on that single atomic database mechanism rather
than duplicating it in the service.
